Master Download Manager is built on third-party software. This file lists
every component that is **bundled in the distributed Windows build**, its

in the `licenses/` folder next to the program (generated by

Master Download Manager's own source code (the `ytd/` package, the GUI, the
browser extensions and build scripts) is not covered by any of the licenses
below. It is copyright (c) 2026 the Master Download Manager author, all rights
reserved, and is not released under an open-source license — see
`docs/LICENSING.md`.

The tables below were written for Master Download Manager 4.1.0 (multimedia

## 0. AB Download Manager (design reference)

Master Download Manager 4.0 adopted several techniques after studying
**AB Download Manager** 1.11.1 by AmirHossein Abdolmotallebi
(https://github.com/amir1376/ab-download-manager, Apache License 2.0) and its
browser integration (https://github.com/amir1376/ab-download-manager-browser-integration,
Apache License 2.0). They were re-implemented independently in Python; **no
AB Download Manager source code, assets, icons or branding are included**.
Adapted ideas:

* dynamic splitting of the busiest download segment with a safe zone ahead
  of the active writer, and an even initial split (`ytd/providers/http.py`)
* a global speed limiter chained with per-download limiters (`ytd/bandwidth.py`)
* named queues with per-queue concurrency, weekday start/stop schedules and
  stop-when-empty (`ytd/queues.py`, `ytd/scheduler.py`)
* a cancellable countdown before a power action (`ytd/gui/power_dialog.py`)
* extension-based default file categories (`ytd/categories.py`)
* the main-window layout (category tree + queues sidebar, icon toolbar,
  download table, status bar) and browser-download capture with file-type,
  minimum-size and site filters (the extension's `ytdShouldCapture`)

The Apache-2.0 license text is included in `licenses/ab-download-manager/`.

## 6. Runtime network use

The application contacts the network **only** for the downloads the user
requests (websites, CDNs, BitTorrent peers/trackers/DHT) and for update checks:
the GitHub Releases API of the official repository, at most once a day while
the app runs (Settings → Updates; interval configurable, can be turned off) and
when the user clicks Check for Updates - either the public download repository
or, if the user chose it, a private releases repository read with the user's
own read-only token. An update is downloaded only after the user clicks
Download Update, and installed only after Install Update and only if its signed
manifest verifies. It never downloads
yt-dlp, scripts, or binaries from GitHub/npm at runtime.
